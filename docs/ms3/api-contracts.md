## 1. Cross-cutting conventions

### 1.1 Versioning and content type

| Rule | Value |
| --- | --- |
| Application prefix | `/v1` |
| Health / readiness | Outside `/v1` (`GET /health`, `GET /ready`) |
| Content type | `application/json` request and response bodies |
| Timestamps | ISO 8601 UTC strings (e.g. `2026-11-19T02:00:00.000Z`) |
| Resource IDs | UUID strings generated by the database. Clients treat them as opaque. Prefixed demo ids are not accepted or returned |
| Request ID | Fastify request id; echoed on every error envelope |

### 1.2 Auth modes and headers

Reuse Phase 1 `AUTH_MODE`:

| Mode | Behavior |
| --- | --- |
| `disabled` | `request.authUser` stays `null`. Public GETs allowed where marked public. All mutations and `requireAuth` **fail closed** with `UNAUTHENTICATED`. |
| `test` | Trusted development / CI identity via `X-Sesh-Test-User-Id` only. Refused at startup when `NODE_ENV=production`. |
| `managed` | Reserved. Not implemented. `request.authUser` stays `null` and `requireAuth` fails closed. Test headers are ignored. |

**Test-mode identity header (`AUTH_MODE=test` and `NODE_ENV` is `development` or `test`):**

```http
X-Sesh-Test-User-Id: <user-uuid>
```

`X-Sesh-Test-School-Id` is ignored. Campus comes from `users.primary_school_id`.

Rules:

- Ignore test headers when `AUTH_MODE` is not `test`.
- A present `X-Sesh-Test-User-Id` in `test` mode must match an `ACTIVE` user with a primary school. Otherwise the request is `401 UNAUTHENTICATED` (it is not an anonymous request).
- A missing header leaves the viewer anonymous.
- Do not accept caller-controlled user ids, host ids, or school ids from JSON bodies.
- Create and patch schemas are strict and reject `schoolId`, `hostId`, and `creatorId`.
- Public discovery works with no auth headers.
- `NODE_ENV=production` with `AUTH_MODE=test` fails environment validation before listen.

`request.authUser` shape:

```ts
{ id: string; schoolId: string } | null
```

`GET /v1/session` returns `{ "user": { "id": string, "schoolId": string } | null }`. It is an auth probe, not a product resource. `GET /v1/protected` remains the fail-closed probe and returns `{ "userId", "schoolId" }` only after `requireAuth`.

### 1.3 Error envelope

Unchanged from Phase 1 / MS3:

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "The request contains invalid data.",
    "requestId": "req-…",
    "details": {}
  }
}
```

| Code | HTTP | Typical use |
| --- | --- | --- |
| `VALIDATION_ERROR` | 400 | Zod / constraint failures on input |
| `UNAUTHENTICATED` | 401 | Missing identity when required; `AUTH_MODE=disabled` on protected ops |
| `FORBIDDEN` | 403 | Authenticated but not permitted (e.g. non-owner edit, invite-only join) |
| `NOT_FOUND` | 404 | Missing resource **or** resource hidden from this viewer (anti-enumeration) |
| `CONFLICT` | 409 | Duplicate membership/request, capacity race loss, stale state |
| `RATE_LIMITED` | 429 | Rate limit |
| `INTERNAL_ERROR` | 500 | Unexpected; no stack traces to clients |

**Capacity:** `409 CONFLICT` with `details.reason` `"CAPACITY_FULL"`. Do not add a top-level `CAPACITY_FULL` code. Phase 4 maps this pair onto the mock adapter’s `CAPACITY_FULL`.

**Restricted visibility:** `NOT_FOUND` when the viewer must not learn that a restricted, draft, cancelled, disbanded, or other-campus resource exists. `FORBIDDEN` when the viewer may know the resource exists but cannot perform the action (non-host edit of a visible event, invite-only join, declined re-request, creator leave).

`details` for `VALIDATION_ERROR` is included only when `NODE_ENV !== "production"`.

`details.reason` is always returned for `CONFLICT` and `FORBIDDEN`, including production, and only for:

`CAPACITY_FULL`, `DUPLICATE_MEMBERSHIP`, `DUPLICATE_REQUEST`, `IDEMPOTENCY_KEY_REUSED`, `INVITE_ONLY`, `JOIN_DECLINED`, `CROSS_CAMPUS`, `TRANSFER_TARGET_NOT_MEMBER`.

No other `details` keys are public.

### 1.4 Idempotency

- `POST /v1/events` and `POST /v1/events/:eventId/move-groups` accept `Idempotency-Key` (1–128 characters, no whitespace).
- First successful create returns **201** and stores the response for 24 hours.
- The same authenticated user, method, route template, key, and equivalent validated body returns **200** with the stored JSON and does not insert another row.
- The same key with a different body returns `409 CONFLICT` and `details.reason` `"IDEMPOTENCY_KEY_REUSED"`.
- Failed requests do not consume the key. Concurrent duplicates produce one row; the loser receives the **200** replay.
- Storage is the shared `idempotency_keys` table specified in `docs/ms3/contract-decisions.md`. Events owns the migration; Move Groups uses that table.

### 1.5 Pagination (cursor)

List endpoints that can grow (Events discovery first):

**Query:**

| Param | Meaning |
| --- | --- |
| `limit` | Page size (default `20`, max `50`). Anything else is `VALIDATION_ERROR` |
| `cursor` | Opaque server cursor from the prior page. Invalid encoding is `VALIDATION_ERROR` |

**Response wrapper:**

```json
{
  "data": [ /* resource views */ ],
  "page": {
    "nextCursor": "opaque-or-null",
    "limit": 20
  }
}
```

Sort for events: ascending `startAt`, then `id`. `nextCursor` is JSON `null` on the last page.

Server encoding, which clients must not depend on: base64url without padding of UTF-8 JSON `{"s":"<startAt ISO>","i":"<uuid>"}`.

### 1.6 Campus scoping

Every campus-scoped entity carries `schoolId`. Authenticated lists default to `request.authUser.schoolId`. A provided `schoolId` that differs from the viewer’s primary school is `403 FORBIDDEN` with `details.reason` `"CROSS_CAMPUS"`. Guests must pass `schoolId` (`VALIDATION_ERROR` if missing) and only receive `PUBLIC` + `PUBLISHED` rows for that school. A resource whose school does not match the scoped campus is `NOT_FOUND`, including for the stored host id. Phase 3 does not authorize non-primary affiliations.

### 1.7 Projection principle

- DB / internal records ≠ public JSON.
- Responses mirror frontend **viewer projections** (`EventView`, `MoveGroupView`, roster masking), not raw records.
- Never return `privateAddress`, hidden member IDs/avatars, or `externalChatLink` unless authorization unlocks them (`unlockedPrivateAddress`, `unlockedExternalChatLink`).

## 3. Events API — routes outline

Base: `/v1/events`

### 3.1 Discovery and CRUD

| Method | Path | Auth | Purpose |
| --- | --- | --- | --- |
| `GET` | `/v1/events` | Optional | Campus discovery with filters + cursor pagination |
| `GET` | `/v1/events/:id` | Optional | Viewer-projected event detail |
| `GET` | `/v1/events/:id/public-metadata` | None | Safe OG / link preview metadata |
| `POST` | `/v1/events` | Required | Create event; owner = authenticated user |
| `PATCH` | `/v1/events/:id` | Required | Host-only partial/full update |
| `DELETE` | `/v1/events/:id` | Required | Host-only cancel (soft: status → `CANCELLED`) |

#### `GET /v1/events` query params

| Param | Values / notes |
| --- | --- |
| `schoolId` | Required for guests. Defaults to the authenticated user’s primary school. A mismatch is `CROSS_CAMPUS` |
| `category` | `ALL` or domain category |
| `price` | `ALL \| FREE \| PAID` |
| `timeWindow` | `ALL \| HAPPENING_NOW \| TONIGHT \| THIS_WEEKEND \| UPCOMING` |
| `search` | Optional text; server-side filter (not full-table dump) |
| `includeDraftsOwnedByViewer` | `true` only meaningful when authenticated |
| `limit`, `cursor` | Pagination |

Response: `{ data: EventView[], page }` — only events `canViewEvent` allows for the viewer’s campus. Cancelled rows are excluded. Drafts are included only for the host when `includeDraftsOwnedByViewer=true`. Order is `startAt` ascending, then `id` ascending. Cursor encoding is in §1.5 and `contract-decisions.md`.

#### `POST /v1/events` body (create)

Align with `CreateOrUpdateEventInput`:

```json
{
  "title": "…",
  "description": "…",
  "category": "Clubs",
  "startAt": "…Z",
  "endAt": "…Z",
  "venue": "…",
  "publicDisplayLocation": "…",
  "privateAddress": "…",
  "addressPrivacy": "PUBLIC_VENUE",
  "visibility": "PUBLIC",
  "status": "PUBLISHED",
  "coverImage": "https://…",
  "capacity": 100,
  "isFree": true,
  "priceLabel": "Free",
  "amountUsd": null,
  "customAllowedUserIds": []
}
```

Validation highlights (mirror frontend + DB constraints):

- `endAt` > `startAt`
- Capacity positive integer when present
- Title/description/venue length bounds per Zod form schemas
- `schoolId` and `hostId` are not body fields. The host is the authenticated user and the campus is that user’s primary school.
- Strict JSON: unknown keys, including `schoolId` / `hostId`, are `VALIDATION_ERROR`.

Publishing (`status: "PUBLISHED"` on create, or a draft patched to `PUBLISHED` with no existing attendance row) inserts host `GOING`. An existing host `INTERESTED` or `GOING` row is not overwritten by publish. Move Group create sets the creator’s parent-event attendance to `GOING` and does not clear a save.

#### `PATCH /v1/events/:id`

Same fields as create (partial patch allowed). Host-only. Preserve consistent state on cancel/edit.

#### `DELETE /v1/events/:id`

Soft-cancel: set `CANCELLED`. Response `200` `{ "id", "status": "CANCELLED" }`. Later `GET`s are `NOT_FOUND` for every viewer, including the host. Hard delete is out of scope. Non-host delete of a visible event is `FORBIDDEN`; delete of a hidden event is `NOT_FOUND`.

### 3.2 Attendance and saves

Phase 2 models **responses** and **saves** as separate relations. Public contract:

| Method | Path | Auth | Body / notes |
| --- | --- | --- | --- |
| `PUT` | `/v1/events/:id/attendance` | Required | `{ "response": "GOING" \| "INTERESTED" \| null }` — `null` removes RSVP |
| `PUT` | `/v1/events/:id/save` | Required | `{ "saved": true \| false }` |

Responses return updated `EventView` for the viewer.

There are no shortcut aliases. Going, interested, and clear RSVP are the attendance `PUT`. Save and unsave are the save `PUT`.

The viewer must be allowed to view the event; otherwise `NOT_FOUND`. Both responses return the updated `EventView`.

## 4. Move Groups API — routes outline

Use **event-nested create/list** and **group-id for lifecycle** (groups live under an event; detail routes use the group id).

| Method | Path | Auth | Purpose |
| --- | --- | --- | --- |
| `GET` | `/v1/events/:eventId/move-groups` | Optional | List groups viewer may see for event |
| `POST` | `/v1/events/:eventId/move-groups` | Required | Create group on published event |
| `GET` | `/v1/move-groups/:id` | Optional | Group detail + roster projection |
| `PATCH` | `/v1/move-groups/:id` | Required | Owner settings update |
| `POST` | `/v1/move-groups/:id/join` | Required | Open join **or** create join request (by `joinMode`) |
| `POST` | `/v1/move-groups/:id/leave` | Required | Non-owner leave |
| `POST` | `/v1/move-groups/:id/join-requests/:requestId/approve` | Required | Owner approve (transactional) |
| `POST` | `/v1/move-groups/:id/join-requests/:requestId/decline` | Required | Owner decline |
| `DELETE` | `/v1/move-groups/:id/members/:userId` | Required | Owner remove member |
| `POST` | `/v1/move-groups/:id/transfer-ownership` | Required | Owner transfer (`{ "newOwnerUserId": "…" }`) |
| `POST` | `/v1/move-groups/:id/disband` | Required | Owner disband (soft) |

### 4.1 Create / update bodies

Create (`CreateMoveGroupInput`-aligned):

```json
{
  "name": "…",
  "note": "…",
  "capacity": 6,
  "discoverability": "PUBLIC",
  "joinMode": "REQUEST_TO_JOIN",
  "meetupTime": "…Z",
  "meetupSpot": "…",
  "externalChatLink": "https://…"
}
```

`eventId` comes from the path. The body must not include `eventId` or `creatorId`. The creator becomes the sole active member with role `CREATOR`. Capacity is an integer from 2 through 50. The parent event must be `PUBLISHED`, same campus, and visible to the creator. First successful create is **201** (or **200** on idempotent replay).

Update returns **200**. Capacity cannot drop below the active member count (`CONFLICT` without `CAPACITY_FULL`).

### 4.2 Join semantics

`POST .../join` optional body: `{ "note": "…" }`. Success is **200** and the viewer `MoveGroupView`.

| `joinMode` | Behavior |
| --- | --- |
| `OPEN_JOIN` | Atomic insert of an active `MEMBER` row if capacity remains |
| `REQUEST_TO_JOIN` | Create a `PENDING` request |
| `INVITE_ONLY` | Invited users create a `PENDING` request. Anyone else gets `FORBIDDEN` and `details.reason` `"INVITE_ONLY"` |

| Situation | Result |
| --- | --- |
| Not visible | `NOT_FOUND` |
| Guest | `UNAUTHENTICATED` |
| Active member | `CONFLICT` `DUPLICATE_MEMBERSHIP` |
| Pending request exists | `CONFLICT` `DUPLICATE_REQUEST` |
| Prior request `DECLINED` | `FORBIDDEN` `JOIN_DECLINED` |
| Active members `>= capacity` | `CONFLICT` `CAPACITY_FULL` |

Approve and open-join use a transaction and a row lock on the group. One remaining seat admits one user. The loser receives `CONFLICT` / `CAPACITY_FULL`. Leave and remove set `left_at` and keep the historical row. The creator cannot leave or be removed (`FORBIDDEN`).

### 4.3 Transfer ownership

Required by MS3. The mock adapter has no transfer method; these rules are the API contract:

- Caller must be the current creator.
- Body is `{ "newOwnerUserId": "<uuid>" }`.
- Target must be a different active member (`left_at` null) on the same campus. Otherwise `FORBIDDEN` with `details.reason` `"TRANSFER_TARGET_NOT_MEMBER"`.
- One transaction: previous creator becomes `MEMBER`, target becomes `CREATOR`. Exactly one active creator remains.

### 4.4 Disband

Soft-disband (`status = DISBANDED`). Response `200` `{ "id", "status": "DISBANDED" }`. Later `GET`s are `NOT_FOUND` for every viewer. Phase 4 maps that `404` to the mock disbanded state. Do not return a disbanded group view.

## 5. Authorization service (contract-level)

Routes call `api/src/modules/authorization/**`. They do not copy `web/src/lib/permissions/policies.ts`.

| Export | Decision |
| --- | --- |
| `areAcceptedFriends` | `ACCEPTED` only, either direction, and no block either way |
| `isBlockedPair` | Block in either direction |
| `canViewEvent` | Visibility, draft/cancel, audience, accepted friendship, campus |
| `canEditEvent` | Host, same campus, not cancelled |
| `canRevealAddress` | Address privacy matrix in `contract-decisions.md` §7 |
| `canViewMoveGroup` | Parent visibility, not disbanded, discoverability |
| `projectRoster` | Creator visible; members see unblocked identities; non-members see accepted friends only |
| `assessJoin` | Join / request / denial in §4.2 |
| `canManageGroup` | Active creator on the same campus |

Friendship access ignores `PENDING`, `DECLINED`, and `CANCELLED`. Blocks remove friendship visibility, `friendsGoing`, and roster identity, including for accepted members. The creator stays visible. Public events stay visible to a blocked user.

`isFullRosterVisible` is true only when the viewer is an active member or creator and nobody was masked. That differs from the frontend flag, which is true for every accepted member.

Development identities exist only through `AUTH_MODE=test`. `disabled` and `managed` cannot mutate.

## 8. Resolved decisions

The items that were open in the draft are frozen in `docs/ms3/contract-decisions.md`:

1. Public ids are UUIDs.
2. Idempotent create is **201** the first time and **200** on replay.
3. Cancelled events and disbanded groups return a small receipt from the mutating verb, then `NOT_FOUND` on `GET`.
4. Ownership transfers only to another active member.
5. Capacity failure is `CONFLICT` + `details.reason` `"CAPACITY_FULL"`.
6. Publish auto-marks the host `GOING` when they have no attendance row. Move Group create sets the creator to `GOING`.
7. Blocks cancel friendship access and roster identity; they do not hide public events.
8. Event cursors are base64url JSON `{"s","i"}`. Idempotency keys are retained for 24 hours in `idempotency_keys`.
